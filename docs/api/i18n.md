# Internationalization (i18n)

SigPro ships a minimal i18n layer for translating UI strings and switching languages reactively. It is a small module with three exports:

- **`addLang(translations)`** — register translation dictionaries.
- **`setLocale(locale)`** — switch the active locale.
- **`currentLocale`** — signal holding the active locale.
- **`t(key)`** — reactive translation getter.

No external dependencies, no ICU pluralization, no message formatting. Just key → string lookup with reactivity.

---

## Signatures

```typescript
addLang(translations: Record<string, Record<string, string>>): void
setLocale(locale: string): void
currentLocale: Signal<string>
t(key: string): () => string
```

> **Availability:** All exported from the SigPro module. Import them by name (`import { addLang, setLocale, t, currentLocale } from 'sigpro'`).

---

## Basic Usage

Register translations, set a locale, and read keys.

```js
addLang({
  en: { hello: "Hello", goodbye: "Goodbye" },
  es: { hello: "Hola",  goodbye: "Adiós" }
});

setLocale("en");

const App = () => div(
  h1(t("hello")),
  p(t("goodbye"))
);

mount(App, "#app");
```

`t("hello")` returns a **function** that reads the current locale. When passed as a child to `h()`, it's treated as a reactive expression: it re-evaluates whenever `currentLocale` changes. If the key is missing, the function returns the key itself (`"hello"`), so nothing breaks during development.

---

## `addLang` — Registering Translations

`addLang` accepts an object keyed by locale code. Each locale is an object of `key: string` pairs.

```js
addLang({
  en: {
    greeting: "Hello, {name}",
    save: "Save",
    cancel: "Cancel"
  },
  es: {
    greeting: "Hola, {name}",
    save: "Guardar",
    cancel: "Cancelar"
  }
});
```

You can call `addLang` multiple times. It **merges** into the existing dictionaries rather than replacing them:

```js
addLang({ en: { hello: "Hello" } });
addLang({ en: { goodbye: "Goodbye" } });
// en dictionary now has: { hello: "Hello", goodbye: "Goodbye" }
```

This is useful for splitting translations by feature or loading them lazily.

## `setLocale` — Switching Languages

```js
setLocale("es");
```

The call is a no-op if the locale has no dictionary registered. To avoid accidentally setting a locale that doesn't exist, only locales previously passed to `addLang` are accepted.

```js
addLang({
  en: { title: "Dashboard", action: "Save" },
  es: { title: "Panel",     action: "Guardar" }
});

setLocale("en");

const App = () => div(
  h1(t("title")),
  button({ onclick: () => alert(t("action")()) }, t("action")),
  div({ style: "margin-top: 1em" },
    button({ onclick: () => setLocale("en") }, "English"),
    button({ onclick: () => setLocale("es") }, "Español")
  )
);

mount(App, "#app");
```

Clicking a language button re-renders every element that used `t(...)`. Because `t()` returns a reactive function, the whole UI switches language at once.

## `currentLocale` — Active Locale Signal

`currentLocale` is a signal. Read it to know which locale is active, write to it to switch (equivalent to `setLocale` but without the validation).

```js
currentLocale();         // → "en"
currentLocale("es");     // switch to "es"
```

You can use it in a reactive child to display the current locale:

```js
div(() => `Current language: ${currentLocale()}`);
```

Or observe it with `watch`:

```js
watch(currentLocale, (nuevo, viejo) => {
  console.log(`${viejo} → ${nuevo}`);
});
```

> **Prefer `setLocale`** for switching. It validates that the locale exists. `currentLocale(v)` writes directly and will silently accept a locale with no dictionary, causing every translation to fall back to the key.

---

## `t(key)` — Reactive Getter

```js
const textFn = t("hello");   // returns a function
textFn();                    // → "Hola"
```

- Returns a **function** that re-evaluates when the locale changes.
- The function reads `currentLocale()` internally, so it subscribes to changes when called inside a reactive context.

Use it in reactive child positions:

```js
h1(t("hello"));              // shortest
h1(() => t("hello")());      // more explicit
```

Both work. The first is shorter and clearer; the second spells out that it's a reactive expression.

### Reading outside a reactive context

If you need the string *right now* (for a `console.log`, an `alert`, or any imperative code), just call the function:

```js
console.log(t("hello")());   // → "Hola"
alert(t("goodbye")());       // → "Adiós"
```

There is no separate imperative API. `t(key)()` is the way.

### Side-by-side

```js
addLang({
  en: { msg: "Hello" },
  es: { msg: "Hola" }
});

setLocale("en");

const App = () => div(
  p(() => `Imperative read: ${t("msg")()}`),   // set once, never updates
  p(t("msg")),                                  // reactive
  button({
    onclick: () => setLocale(currentLocale() === "en" ? "es" : "en")
  }, "Toggle language")
);

mount(App, "#app");
```

The first paragraph captures the value at mount time and never updates. The second paragraph re-renders whenever the locale changes.

## Missing Keys

If a key is not found in the current locale's dictionary, `t` returns the key itself:

```js
addLang({ en: { hello: "Hello" } });
setLocale("en");

t("hello")();   // → "Hello"
t("missing")(); // → "missing"
```

This is intentional. In development, seeing the key tells you what's missing. In production, you have a visible bug rather than an empty string or a crash.

If you want a fallback to a specific locale, register a fallback locale first and set it as default:

```js
addLang({ en: { hello: "Hello" }, es: { hello: "Hola" } });
setLocale("en"); // fallback locale
```

The current implementation does **not** do fallback chains (e.g. `fr-CA` → `fr` → `en`). If a key is missing in the active locale, you get the key. Full fallback chains are on the roadmap, not in the current core.

## What SigPro i18n Is Not

- **No pluralization.** No ICU MessageFormat, no `{count, plural, ...}`. Use `computed` to build plural strings manually.
- **No interpolation.** `"Hello, {name}"` is stored verbatim. Substitution is your responsibility.
- **No fallback chains.** Missing keys return the key, not a fallback translation.
- **No lazy loading.** `addLang` is synchronous. For code-split dictionaries, call it after fetching.
- **No date/number formatting.** Use `Intl` directly.

## Interpolation by Hand

SigPro doesn't interpolate. Combine `computed` with `.replace`:

```js
addLang({
  en: { greeting: "Hello, {name}" },
  es: { greeting: "Hola, {name}" }
});

const name = signal("Ada");

const greeting = computed(() =>
  t("greeting")().replace("{name}", name())
);

h1(greeting);
```

Or a small helper if you do this often:

```js
const tr = (key, vars = {}) => () =>
  Object.entries(vars).reduce(
    (s, [k, v]) => s.replace(`{${k}}`, v()),
    t(key)()
  );

h1(tr("greeting", { name }));
```

The helper is 5 lines and covers the 95% case.

## Pluralization by Hand

```js
addLang({
  en: { items_one: "1 item", items_many: "{n} items" },
  es: { items_one: "1 elemento", items_many: "{n} elementos" }
});

const count = signal(0);

const label = computed(() =>
  count() === 1
    ? t("items_one")()
    : t("items_many")().replace("{n}", count())
);
```

Ten lines of logic you'd write anyway. SigPro doesn't ship a plural engine because for most apps, the 2-form split (`one` / `many`) is enough, and for the apps where it isn't, you need ICU and would use a real i18n library on top.

## Persisting the Locale

Combine with `local()` to remember the user's choice across reloads:

```js
const userLocale = local("app-locale", "en");
setLocale(userLocale());

watch(userLocale, (v) => setLocale(v));
```

Or sync it globally in a store module:

```js
// store.js
import { local, setLocale, watch } from "./sigpro.js";

const userLocale = local("app-locale", "en");
setLocale(userLocale());
watch(userLocale, (v) => setLocale(v));

export { userLocale };
```

Calling `setLocale` once at module load is enough. When the user switches language later, `watch` handles the sync.

| Goal | Code |
| :--- | :--- |
| Register translations | `addLang({ en: { hello: "Hello" } })` |

| Imperative read | `t("hello")()` |
| Current locale | `currentLocale()` |
| Subscribe to locale changes | `watch(currentLocale, fn)` |
